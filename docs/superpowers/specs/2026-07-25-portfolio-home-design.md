# Kid Portfolio 首页设计规格

日期：2026-07-25

## 1. 目标与参考基准

本项目从空目录开始，制作一个以桌面端为主要还原目标的个人作品集首页，并为移动端提供适配版本。

参考图的职责明确分开：

- `Portflio Test 1.5.jpg`：决定页面内容、整体构图、排版、色彩、空间比例和常态视觉。
- `SELECTED WORK.png`：决定 Selected Work 三张项目卡片的独立悬停状态。
- `hero-interaction-storyboard-chaos-to-order-v1.png`：决定 Hero 从混沌到秩序的动画叙事。

页面不重新设计图一的内容。分镜图中的英文标题不替换图一的 `Design for Business Momentum`。

## 2. 技术方案

使用 Vite、原生 HTML、CSS 和 JavaScript。Hero 采用“背景视频 + DOM”方案：

- 背景视频承担数字空间、混沌收束、数字雨、人物出现与最终稳定画面。
- DOM 承担导航、标题、说明、按钮和可访问交互。
- 少量 CSS 光晕与遮罩用于融合视频和文字，但不伪造复杂粒子系统。
- 页面不引入 React、Three.js 或后端服务。

选择该方案的目标是优先保证电影化画面、构图一致性和跨设备稳定性。鼠标不会实时改变视频内部的数字轨迹。

## 3. 页面结构

页面包含五个主要区域：

1. Hero：满视口背景视频、顶部导航、中心标题、说明与行动按钮。
2. Approach：左侧方法论标题，右侧五条工作方法。
3. Selected Work：一张横向主卡片和两张并列副卡片。
4. Experience：左侧个人定位，右侧经历列表。
5. Contact：数字雨背景、联系信息、行动按钮与页脚信息。

桌面端以参考图的窄内容栏和大面积黑色留白为核心，不把内容铺满整个屏幕。移动端改为单列，但保留相同的信息顺序和视觉层级。

## 4. Hero 动画

Hero 视频按以下叙事制作或接入：

1. 初始阶段：画面显示混沌数字空间，前景数字更大、更虚，背景数字更细密。
2. 扰动阶段：鼠标首次进入 Hero 后，播放数字被扰动的段落。该反馈由视频播放触发，不声称为实时粒子物理。
3. 收束阶段：数字逐渐被拉成竖向轨道并形成数字雨。
4. 人物阶段：中央人物从数字与辉光中逐渐显现。
5. 稳定阶段：画面停留在与图一接近的最终 Hero 构图，DOM 标题、说明和按钮渐显。

若暂时没有最终视频资产，开发阶段使用参考图裁切出的静态 Hero 画面作为后备背景，并保留视频接口。最终交付状态必须清楚标记视频资产是否已经接入，不能把静态后备画面描述成完成的视频动画。

视频行为：

- 静音、内联播放，不显示原生控制条。
- 桌面端首次加载后自动播放开场；鼠标首次进入可触发后续段落或重播交互段。
- 稳定状态结束后停留在最终画面，不进行明显循环跳切。
- `prefers-reduced-motion` 开启时直接显示稳定状态。
- 移动端不依赖悬停，自动播放简化版本；系统禁止自动播放时显示稳定后备图。

## 5. 覆盖式滚动

Hero 高度为一个视口，并作为页面底层的 sticky 区域。Approach 及后续内容位于更高层级：

- 用户开始向下滚动时，Hero 保持不动。
- Approach 黑色面板从视口底部上移并覆盖 Hero。
- Approach 完全覆盖后，后续区域按正常文档流滚动。
- 向上滚动时按相反顺序重新露出 Hero。

Approach 面板必须是实色或接近实色黑色，避免 Hero 视频透出影响正文阅读。

## 6. Selected Work 悬停

三张卡片独立响应悬停：

- 默认状态使用图一中的青黑数字空间图。
- 主卡悬停后显示 ANKER Innovations 品牌画面。
- 左下卡悬停后显示储能产品营销画面。
- 右下卡悬停后显示品牌陈列与包装系统画面。
- 鼠标移出后回到默认状态。

图片使用交叉淡化和轻微缩放完成切换，持续时间约 450–650ms。卡片尺寸、文字、边框和按钮位置不改变，避免布局跳动。

键盘聚焦卡片时显示与悬停相同的项目状态。触屏设备没有悬停，因此默认直接展示真实项目视觉，保证项目内容可识别。

## 7. 响应式规则

桌面端是视觉验收主基准：

- 以参考图宽高关系为依据控制内容栏宽度、区块间距和字号比例。
- Hero 保持满视口，背景使用 `cover`，人物焦点保持水平居中。
- Selected Work 保持一大两小结构。

移动端：

- 导航缩减为品牌名与菜单入口。
- 标题和正文按视口宽度缩放，避免机械压缩桌面字号。
- Approach、Selected Work 和 Experience 改为单列。
- 项目卡片直接显示真实项目图。
- 覆盖式滚动保留，但降低 Hero 视频运动强度并避免强制滚动吸附。

## 8. 可访问性与性能

- 所有可操作项目使用真实链接或按钮，并提供键盘焦点样式。
- 图片提供描述性替代文本。
- 视频提供后备图，不让视频加载阻塞标题和导航。
- 首屏视频优先使用适合网页的 MP4/WebM，并控制桌面、移动端两个版本的码率。
- 页面文字与背景保持足够对比度。
- 支持 `prefers-reduced-motion`。

## 9. 验收标准

- 桌面端页面结构、比例、颜色、字体层级和留白与图一保持一致。
- Hero 能完成“混沌—收束—人物出现—标题出现”的视频叙事；若缺少最终视频，只能作为明确标注的待替换资产接口交付。
- Approach 能以覆盖方式上移遮住固定 Hero。
- Selected Work 三张卡片可独立悬停、键盘聚焦和恢复。
- 移动端无横向溢出，核心内容按单列正常浏览。
- 本地构建通过，浏览器控制台无错误，并完成桌面端与移动端截图对照。
